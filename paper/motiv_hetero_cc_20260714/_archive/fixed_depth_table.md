## 读表要点

1. 份额拐点在 Kmax 越过实测上限之后（m4 起），Kmin 追平上限（m5）时
   RDMA 拿到 20-22G（约公平份额一半）。
2. M4 区（75%/126%）份额轮间方差大（GBN 2.0-9.5G、SR 5.0-9.7G），
   硬件时间序列显示份额在几十秒尺度游走——60s 窗口不足，引用需长跑。
3. GBN 线上税 39-76% vs SR 9-29%（m4r2 的 76%/29% 发生在份额游走期，
   典型稳态对照是 m4r3 的 40%/11% 与 m5 的 39%/9%）。
4. SR 的系统总 goodput 在所有配对中都更高（+0.3 到 +7.1G），m5 差距
   最大：GBN 的重传垃圾挤掉 TCP 9.5G。
5. m3-GBN 是不稳定风暴点：乱序 1.4 万、ECN 标记爆到 5000 万、总吞吐
   掉 9G；SR 同配置完全干净——"GBN 在标记带贴近溢出时进入风暴区"。
6. m5-SR 的 DCQCN 参与度弱（CNP 3.4 万 vs GBN 33 万）：SR 窗口纪律让
   队列大多够不到 Kmin=43M。引用 m5 时需披露这个不对称。
7. 所有档位跑动中 RTT 1.8-3.6ms（队列在几十 MB 运行）——低延迟代价
   贯穿整个配置族。

数据目录：gbn/sr_{b16m,m2,m3,m4,m4r2,m4r3,m5}；m4r2 起含 vpm_series.csv
（1Hz 硬件时间序列）。

## 1.2.3：CC 恢复激进度扫描（健康工作点 [71%,120%] = TC5+alpha_1_4+m4，×3 遍均值）

图 motiv12_fig_cc_scan。旋钮：RDMA rpg_time_reset/ai/hai（slow 1200/1/10、
default 300/5/50、fast 75/50/500，host PF sysfs）；TCP cubic beta（slow 410、
default 717、fast 922）。每格 3 遍均值（RDMA/TCP/总，G）：

| 配置 | GBN | SR | 备注 |
|---|---|---|---|
| RDMA-slow | 3.13/87.0/90.2 | 2.35/91.6/94.0 | 方差大(0.8-4.4) |
| default | 6.37/84.8/91.1 | 5.88/87.9/93.8 | 同 m4 漂移带 |
| **RDMA-fast** | **12.36/2.79/15.1** | 10.92/83.1/94.0 | GBN 三遍全崩(总 4.6-35.9)，12-14万 NAK+死流；SR 稳 |
| TCP-slow | 14.61/71.6/86.2 | 14.99/78.6/93.5 | beta 低→RDMA 得利 |
| TCP-fast | 0.78/87.0/87.8 | 2.71/91.4/94.1 | beta 高→RDMA 回压近饿死 |

三个稳健结论（跨三遍一致）：
1. **RDMA-fast + GBN = 系统性崩溃**：三遍系统总 goodput 4.6/4.9/35.9G，
   均 12-14 万 NAK、1-4 条 QP 卡死——无窗口纪律的激进恢复把链路打成
   重传垃圾场，RDMA 与 TCP 同归于尽。SR 同参数三遍稳定 93-94G 总吞吐、
   0 死流。单遍预览的 GBN 31.13 是崩溃时的一次偏侧分配，误导，已被均值
   与方差修正。
2. **TCP beta 在健康工作点是强旋钮**（原 1.2 深缓冲下完全无效）：
   TCP-fast 把 RDMA 压到 0.78-2.71G，TCP-slow 放到 14.6-15.0G——因为
   贴顶锯齿让 TCP 真的丢包，beta 才进场。这是"搬到健康工作点"的核心收获。
3. **SR 系统总吞吐在所有 5 配置全部 ≥ GBN**（差距 RDMA-fast 最大，
   +79G）；GBN 的份额优势（如 RDMA-fast 的 12.36）都是重传垃圾堆的。

方差警示：m4 工作点份额漂移大（1.2.1 已知），单格 3 遍 min-max 跨度可达
0.7-31。图用均值仅作定性；若需定量份额需更长窗口或更多重复。
