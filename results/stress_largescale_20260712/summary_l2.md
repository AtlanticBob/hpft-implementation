# 大规模 L2：churn（2026-07-12）

L1b 政策瓶颈基线（caps 40/30/20/10G、类权重 7:3/6:4/5:5/3:7、p1=200G）
上叠加 churn：t=45 停整个 vf1 对（租户进出）、t=75 vf1 回来、t=105 停
vf0 的 TCP（类进出）、t=135 vf0 TCP 回来。热 agent（不重启，避免归因
瞬态）。

## 关键：类归因在持续 4 对混合满载下的鲁棒性（用户提示解决）

**症状**：持续 4 对 RDMA+TCP 满载下，类归因对部分 VF 间歇失效——TCP
被测成 0、误记进 RDMA（nfs 掉到 4），进而 TCP 遥测"断流"触发 fail-open、
TCP 失控冲到 34G（40G cap 下本该 12G）。一个观测层的失效经 fail-open
放大成执行层公平性破坏。

**根因与修复（用户提示）**：iperf3 用 `-B ip%dev`（SO_BINDTODEVICE）
强绑定网口，替代 `-B ip`。不绑定时，源地址路由（配合跨对的 rp_filter=2
/ arp_ignore=1）在持续满载下会让 TCP 间歇性走错 VF，接收端 per-VF
netdev 计数器错记 → 类拆分错。强绑定把每对 TCP 钉死在其 VF 上。修复
后 vf0 pre-kill 从 38.5/0（全错）恢复到 27.1/11.8（正确 7:3）。
**教训入 ops_notes**：多 VF 并发 TCP 实验一律用 `%dev` 强绑定。

## churn 动态（强绑定后可测）

- **未触碰对的权重守住**：vf3 全程 0.40（目标 0.43）、vf2 ~0.95（目标
  1.0），邻居租户进出不破坏它们的类权重——控制面隔离成立。
- **类进出的重收敛慢且过冲**：vf0 TCP 停→RDMA ~15s 填满 cap（单 QP
  RDMA 线速锚定 A 爬升慢）；TCP 重入→**大过冲**（峰值 TCP 29.5 / RDMA
  3.1），~20-30s 收敛回 7:3。高速率下重收敛显著慢于 D3 的亚秒级（6G），
  根因同 A 的线速锚定：高 cap 下填补/收敛更慢，TCP -P4 激进 ramp 过冲
  更大。这是高速率 churn 的一个动态边界，值得记录。
