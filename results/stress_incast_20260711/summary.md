# 压测 D4：incast（M3@1ms 首验）+ 租户间权重（2026-07-11 晚）

协议：ethtool 把接收端 p1 降到 100G/25G 制造 root 层短缺（全 VM 的
MaxRate 临时解除让 root 成为 binding 层，与 M3 同口径），四个直连对
RDMA 满需求；租户间权重 5:1/10:1 两流对照；churn 加入瞬态。runner=
d4_run.sh，分析=analyze_d4.py。首轮数据全部作废（见"排障"节），本文
数据来自修复后的干净重跑。

## 结论一（设计级，待用户裁决）：root 短缺区的同步弛豫振荡与利用率回归

同一实验（4 流等权、root=97G）的三方对照：

| 配置 | 每流均值 | 聚合 | 秒级 sd |
|---|---|---|---|
| M3@50ms（旧律，07-09） | 21.9G | ~88G (90%) | ~0 |
| 现律@50ms | 18.5G | 73.9G (76%) | 2.2 |
| 现律@1ms | 13.4G | 53.6G (55%) | 10.2 |

两个因素叠加：**新律在 root 区结构性让出利用率**（probe_cap 余量随
r→ceil 衰减到零 + FR 封顶，把旧律"贴着 ceil×1.05 常态超发"的激进探
测拿掉了——单对场景的稳定正是靠这个换来的）；**1ms 把 root 耦合放大
成全局同步振荡**（root 层零和：任何单流事件改变所有流的 e_f → 标记
相关 → 四条 AIMD 同相俯冲/爬升，周期 2-4s，幅度 3-25G）。四流 spread
仅 2.5%——公平性完好，损的是利用率与平稳性。25G 深短缺同型（聚合
73%，sd 2.1-2.4）。候选方向（均为设计变更）：标记/探测退相（per-fs
相位抖动，RED 式随机化）；root 区专用余量策略；接受现状记为 1ms 在
root 区的已知代价。

## 结论二：权重跟随与 churn（好消息）

- 租户间权重 **5:1 实测 5.05**（vf0 18.37G / vf1 3.64G，各 −9%，
  比例几乎完美）；10:1 实测 6.85（被振荡污染，vf1 +19%）；
- churn 加入（3 稳态 + 1 乐观起步）：**4.7s 收敛**到四流 ±10%，加入
  瞬态 ping max 20ms（M3@50ms 是 114ms——1ms 的瞬态物理代价更小）；
- 全程零丢包，ping avg 0.07-0.26ms——headroom 机制在 root 短缺下仍
  让物理队列近零（尖峰 max 20-128ms 与振荡的攀升相位对应）。

## 排障叙事（首轮作废的原因，三个独立问题）

1. **p1 速度反复翻转留下暂态"延迟病"**：全 fabric 路径空载 RTT 尖峰
   10-200ms（正常 0.1ms），扛过两端 OVS 重启与定速重训，~1 小时后自
   行消退；期间遥测尖峰超过 N2=2s 触发间歇 fail-open。教训：变速类
   实验之间要 ping 验证 fabric 干净，变速次数能省则省。
2. **SF bounce 掉 IP**：`ip link down/up` enp3s0f1s0 会抹掉 10.1.9.x
   地址（遥测双端全断的直接原因）；OVS 重启还会抹掉 rx 的分类规则
   （需重启 rx_agent 幂等重装）。
3. **slew=1.0 语义 bug**（自伤，已修 + 闭环复验 5.58G@6G）：下降分支
   `sent×1.0^dt` 让"关闭斜率限制"变成"预算永不下降"——执行器永远
   停在 fail-open 时代的 193G 预算，律面 md 砍到 58G 也写不下去。
   连带作废了一个曾被误读为"史上最优"的 d4a_noslew 运行（实为乐观
   起步恰好等于树份额的静态预算，不是闭环）。

## slew 终裁：恢复 0.35 常开

d4 重跑（slew 关）证明 root 振荡与 slew 无关；单对 64KB repro 上
slew+地板（5 轮 3 发作，含多轮零发作满带）优于纯地板（2 轮 4 发作）。
语义 bug 修复后两道防御叠加为默认配置。
