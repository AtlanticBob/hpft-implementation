# 令牌桶执行面的验证矩阵（2026-09-08，PCC 里 DCQCN 与 Swift 的定稿版）

环境：四台 sgpu01-04，各 8 VF、每 VF 50 G（devlink 上行 + OVS meter 下行），单交换机 sn5600，四个 p1 口 200 G，接收端口 swp37s0 绑 `hpft_ecn`（800 KB 起标、3.2 MB 满标、20%），PFC 关，TCP 不开 ECN，RDMA MTU 1024（overlay 上净荷上限 177.2 G）、每流集合 4 QP，TCP 每流集合 4 条 Cubic 连接，账本余量 8%。租户 CC 是 `tools/dpu/pcc/rp_rtt_template_dev_main.c` 里的 DCQCN（`0xccd 2`）与 Swift（`0xccd 3`），参数见该目录 README。每场 12 秒，数字是应用净荷 Gb/s：RDMA 是 perftest 的 BW average，TCP 是 iperf3 接收端收到的字节除以客户端的测试时长（iperf3 服务端自己报的速率把 `--start-at` 的等待算进了分母，会低估三到四成，不能用）；"标记"是交换机接收端口 12 秒里的 `ecn-marked-frames` 增量。原始输出在 `runs/`（RDMA 场景 `c_*`，含 TCP 的场景 `e_*`）。

## 4.1 单租户一个流集合：CC 单独 = CC + 桶

| 流 | CC 单独 | 加桶 |
|---|---|---|
| RDMA，DCQCN | 45.54 | 45.52 |
| RDMA，Swift | 45.50 | 45.53 |
| TCP，Cubic，4 条连接 | 46.85 | 44.94 |

TCP 加 HyperFront 低 4%：单个流集合在 50 G 的 VM 上限上，账本给的许可速率略低于 CC 自己顶到上限的位置。

## 4.2 RDMA 与 TCP 打同一 VM（各一个流集合，类权重 1:1）

| 租户 CC | CC 单独 RDMA / TCP | 加桶 RDMA / TCP |
|---|---|---|
| DCQCN | 24.88 / 23.26 | 22.98 / 23.91 |
| Swift | 37.43 / 7.38 | 22.58 / 23.84 |

在这个 50 G 的 VM 上 DCQCN 与 Cubic 单独共存已经接近公平，Swift 与 Cubic 则是 5 比 1；HyperFront 打开后两种情况都到 23 对 24，按账本的内层线上字节算 RDMA 24.6、TCP 25.0，各自 25 G 应得的 98% 与 100%。

## 两台发送端各四个 RDMA 流集合打同一接收端（q_ab，份额 23 G 内层字节 = 21.4 G 净荷）

| 臂 | 合计 | 八个流集合 | 标记 |
|---|---|---|---|
| DCQCN 单独，三场 | 168.7 / 170.7 / 165.9 | 15.3 到 26.7 / 21.1 到 21.6 / 14.2 到 24.2 | 416 万 / 289 万 / 440 万 |
| DCQCN 加桶 | 165.8 | 20.46 到 20.89 | 285 万 |
| DCQCN，等额封顶 min(c, R/N) | 167.1 | 20.82 到 21.00 | 309 万 |
| DCQCN，忽略 CC 的等分 R/N | 163.8 | 20.07 到 20.67 | 1.01 亿 |
| Swift 单独 | 173.2 | 20.88 到 22.40 | 3.3 万 |
| Swift 加桶 | 163.0 | 20.00 到 20.62 | 10.1 万 |

DCQCN 单独运行三场里两场有个别流集合掉到 14 G，是它对丢包重置目标速率后恢复慢的自身行为；桶臂三种组合都均匀。忽略 CC 的等分与桶吞吐相同、公平相同，标记多 35 倍：留着 CC 的价值就是它在账本周期之下把端口队列压住。

## V1 形态（三台发送端各 4 VF，每 VF 一个 RDMA 流集合加一个 TCP 流集合，共 24 个）

| 租户 CC | 合计 | RDMA 类 12 个 | TCP 类 12 个 | 24 个 Jain | 标记 |
|---|---|---|---|---|---|
| DCQCN | 176.0 | 6.96 到 7.05，Jain 1.000 | 7.59 到 7.72，Jain 1.000 | 0.998 | 62 万 |
| Swift | 174.0 | 6.76 到 6.89，Jain 1.000 | 7.58 到 7.73，Jain 1.000 | 0.996 | 14 万 |

每个 VM 的两类应得各 23 G 内层字节，三台发送端各 7.67 G。按内层字节算 RDMA 类 7.5 G（应得的 98%）、TCP 类 8.0 G（104%），两类之间差 6%：TCP 的上探把线上速率顶在许可速率之上一点，RDMA 的 DCQCN 停在许可速率之下一点。
