# HPFT 压力测试战役总结（2026-07-11/12）

这份文档汇总一次系统性压测的全部结果。目标不是复现已通过的验收，而是
把方案 E（DPU 边缘虚拟队列标记的两层公平）在极端条件下顶到边界，找出
它会不会崩、公平性与稳定性的悬崖在哪。战役覆盖七个维度（规模、极端
比例、churn、incast、参数边界、对抗时序，外加一条贯穿始终的发作性
崩塌排查），产出六个已修复的工程缺陷、两个待用户裁决的设计发现、一份
参数敏感性地图。lab 全程运行在 period_ms=1。

数据目录：results/stress_*；本文只给结论与索引，逐项细节见各 summary。

## 一、维度结论一览

| 维度 | 判定 | 一句话 |
|---|---|---|
| D1 规模 | 正向（有墙） | 1ms 控制面 CPU 饱和点 = 28 流集合；开销线性，越墙是周期温和拉长非崩 |
| D2 极端比例 | 正向 | 类权重跟随到 8:1 全部 ±10%，无悬崖，弱类 0.6G 无死锁 |
| D3 churn | 正向 | 让位/回满 p50 0.06-0.22s（比历史快一个量级），四对错相位零串扰 |
| D4 incast | 混合 | 公平性完好（spread 2.5%、5:1 权重 5.05）；但 root 区利用率/振荡有设计级问题 |
| D7 参数边界 | 正向 + 重大发现 | 默认点在平坦区中央，仅两悬崖；**root 振荡是参数问题，V=4 一步治根** |
| D8 对抗时序 | 正向 | on-off 泵在任何节奏下都拿不到超过稳态份额，时序攻击鲁棒 |
| 长稳 D6 | 取消 | 用户指示不做 |
| 故障 D5 | 取消 | 用户指示不做；但排障过程已实测 fail-open 链 |

## 二、修复的工程缺陷（六个，全部已 commit + 验证）

按发现顺序：

1. **TCP 执行面两层覆盖缺口**（commit e427362）。EDT 的 tc filter/fq
   只装在 vf0、pair_state 只播种直连对，导致跨 VF 对的 TCP 完全不受
   pace、28fs 竞争下把每个 dst 的 20G MaxRate 冲到 46-55G。修复=
   edt_ensure.sh（幂等挂载四 VF）+ pace_shim 启动播种全部 pair_state。

2. **RP 跨层活锁**（commit e427362）。预算每次 flush 微变就重臂 RP 的
   settle-hold，积分永远不迈步，被压穿的 level 按比例永久压穿（实测流
   困在 6% 兑现）。修复=tx 侧预算 3% 滞回，让预算准静态、rate 字段照
   常新鲜。

3. **发作性标记风暴的律侧成因**（commit 9e96dde）。探测锚固定
   ceil×1.05 在数学上保证兑现率 >95.2% 的执行器永久超额→VQ 必然
   饱和→周期性风暴。修复=兑现率感知的 probe_cap（余量随 r→ceil 衰减
   到零）+ FR 反弹封顶 + MD 地板锚政策量。

4. **RP 积分下挖过深**（commit 8d8d60b，唯一的 device 码改动，用户
   授权）。积分下挖地板 bud>>7（0.8%）在应用滞后窗口里把 level 挖到
   近零→线速崩塌。修复=地板提到 bud>>2（25%）。验证：地板精确生效在
   0.25，2/3 轮完美。

5. **预算下降斜率**（commit 63ae8b6）。三环极限环（VQ/律/RP 积分 +
   回路延迟）的阻尼手段：预算下降限速 0.35/s，上升自由。

6. **slew-off 语义 bug**（commit 9324e9a，自伤）。关闭斜率限制时
   decay=1.0 让"下降路径"变成"预算永不下降"，执行器停在 fail-open
   预算。修复=slew 关闭时走普通滞回。

发作性崩塌的完整排查链（D2 发现→E1/E2 证伪重传理论→三环极限环→
device 地板→残余尾巴定位到 QP 硬件层）见
results/stress_fix_probe_20260712/summary.md。五层软件修复把发作从
"周期性、均值 1.96G、−57% 深塌"收敛到"~1/10 轮短暂 −27% dip、2/3 轮
完美"，残余尾巴在 RP 之下的 QP 硬件层，超出软件控制面可达范围。

## 三、待用户裁决的设计发现（两个）

**发现一：V_periods 默认 2→4，根治 incast root 区振荡。** D4 暴露
root 短缺区的同步弛豫振荡（四流同相俯冲、聚合 55%、sd 10.2）。D7 的
W2 扫描证明这是参数问题不是机制问题：V 从 2 加到 4，root 区从
46G/48%/sd9.97/相关0.99 跳到 95G/98%/sd0.04、四流 spread 0.0%，且
反超历史 M3@50ms 旧律（23.84 vs 21.9G/流）。W1 证明 V=4 在单对场景
无副作用。机理：V（标记满刻度）加倍让虚拟队列更晚饱和，把同步硬砍
软化成温和涟漪。**建议采纳 V=4 为新默认**，采纳前补一轮更高流数/更
激进参数的锯齿确认。lab 现仍 V=2。

**发现二：root 区利用率的律代际差。** 即便 V=2，现律@50ms 的 root
利用率（76%）也低于 M3 旧律（90%）——probe_cap 的衰减余量换掉了旧律
"贴着 ceil×1.05 常态超发"的激进探测。这是单对稳定性与 root 利用率的
一个显式权衡；V=4 同时解决了两者（root 98% 且单对稳定），所以发现一
一旦采纳，发现二自动消解。

## 四、参数敏感性地图（D7 W1，供论文）

单对两类竞争、27 点单轴扫描，只有两个失稳悬崖，都在"太慢/太粗"方向：

- **a_frac_linerate ≥ 0.001**（默认 0.0005 的 2 倍）：比例崩到 0.50、
  发作、振荡。A 是全系统最敏感旋钮，1ms 下复利放大尤甚。
- **rate_window_s ≥ 0.1**：测量窗跟不上秒级竞争，比例 0.74、发作。

其余全部宽容：β(0.1-0.7)、V(0.5-8)、probe_over(1.0-1.3，含零余量)、
probe_gain(0-100)、slew(0.1-1.0)均无悬崖。本轮修复引入的三个新参数
没有一个是脆弱魔法数。

## 五、平台/运维新增（已并入 ops_notes 与工具）

- **flowtag 碰撞**（平台性质）：src vf1 与 vf2 对一切 dst 同 tag，16
  对只有 12 个可区分键；registry 新增 rdma_flowtags 表，tx_agent_e
  RDMA 键改 (src>dst)。真 32fs 需 qpn-override（挂起）。
- **两个 preflight 脚本**：cross_pair_net.sh（跨对路由）、edt_ensure.sh
  （四 VF EDT 挂载）——host/VF 重建后必须重跑。
- **执行器逃逸绊线**：tx_agent_e 的 log-only 告警（r>1.5×pace 持续
  1s），零误报，超发相精确命中；停摆相（r≪pace）是已知观测盲区。
- **三条新病历**（ops_notes）：p1 变速的暂态延迟病、SF bounce 掉 IP/
  OVS 重启掉规则、"预算永不下降"型执行面失守的辨认。

## 六、遗留项

- V=4 采纳前的高流数确认（属发现一）；
- 真 32fs 的 qpn-override（解锁规模上限最后 12%，工程半天）；
- 发作性崩塌的残余尾巴（QP 硬件层，传输线，超出 device 可达）；
- root 区利用率的律代际差（发现二，V=4 采纳即消解）；
- 控制面 numpy 向量化 / C 重写（把 28fs 墙推到数百/千，论文定位够用
  可不做）；
- 长稳 D6、故障 D5（用户取消，可随时补）。
